# dsh-vps-manager

中文 | [English](README.md)

在 DeepSeek Harness 里管你的 VPS：**点一下看信息、跟 AI 说话干活、从应用商店一键装软件。**

三条路共用同一套执行引擎，所以加锁、备份、任务记录、审计日志只实现一次，从哪个入口进来行为都一样。

---

## 三种用法

| | 看信息 | 跟 AI 说话 | 一键安装 |
|---|---|---|---|
| 怎么用 | `/vps-sysinfo` 这类命令 | "给香港那台配个反代" | 面板 → 应用商店 |
| 走不走模型 | 不走 | 走 | 不走 |
| 花费 | 零 token | 正常 token | 基本为零 |
| 能做什么 | 固定的只读查询 | SSH 能做的都能做 | 经过整理、可重复执行的菜谱 |

---

## 运行要求

- macOS 或 Linux（Windows 自带的 OpenSSH 不支持连接复用）
- Node.js >= 22.13
- **只支持密钥登录。** 不支持密码登录，也不支持需要输密码的 `sudo`——非交互环境下 `sudo` 会把脚本当成密码读走
- 要改系统的操作，远端用户必须是 `root` 或有免密 `sudo`；只读查询两种情况都能用

## 安装

还没发到 npm。从源码装：

```bash
git clone https://github.com/AIcivilization/dsh-vps-manager.git
cd dsh-vps-manager && npm install
```

链接进你的 DSH profile，并加进 bundle 清单：

```bash
ln -s "$PWD" ~/.dsh/profiles/desktop/node_modules/dsh-vps-manager
```

在 `~/.dsh/profiles/desktop/package.json` 的 `dsh.profile.bundles` 里加上 `"dsh-vps-manager"`，然后**重启 DSH**。插件代码在启动时加载，改文件不会热生效。

## 上手

点左边栏的 **VPS 管理** →「+ 添加机器」，向导四步：

1. **填写** —— 地址、端口、用户名、别名、备注、分组
2. **钥匙** —— 自动生成专用的 `~/.ssh/dsh_vps_ed25519`，不动你原有的钥匙
3. **放公钥** —— 三选一，插件全程接触不到你的密码：
   - 复制公钥，粘到服务商后台的「SSH 密钥」（新机器最省事）
   - 复制一行命令，在已经能登录的服务器上执行
   - 一键打开终端，`ssh-copy-id` 已填好，你自己输密码
4. **保存** —— 写入 `~/.ssh/config.d/dsh-vps.conf`，在你的 `~/.ssh/config` 最顶部加一行 `Include`（改前自动备份），然后体检一次

**你自己写的 `~/.ssh/config` 内容永远不会被改写。** 已经在里面的机器可以用「从 ~/.ssh/config 导入」接管，导入后连接字段是只读的。

## 命令

查询类不走模型、不花 token。每条结果第一行是一句摘要——因为 DSH 会把命令结果折叠成一行。

| 命令 | 看什么 |
|---|---|
| **`/vps-help`** | **总入口：全部命令与参数、怎么指定机器、跟 AI 怎么说、面板在哪** |
| `/vps-sysinfo` | 系统、CPU、内存、磁盘、负载、公网 IP |
| `/vps-disk` | 挂载点、inode、最大的几个目录（有时间上限） |
| `/vps-ports` | 监听端口和对应进程 |
| `/vps-services` | 失败的和正在运行的服务 |
| `/vps-net` | 网卡、累计流量、连接数 |
| `/vps-docker` | 容器与磁盘占用 |
| `/vps-ping` | 一行健康状态 |
| `/vps-logs <服务名>` | 最近 100 行日志 |
| `/vps-probe` | 重新体检（系统、init、权限、资源） |
| `/vps-sh [--yes] <命令>` | 在当前机器上执行一条命令，输出进对话；高危命令要加 `--yes` |
| `/vps-q <菜谱id>` | 跑任意一条查询菜谱（没有专属命令的那些） |
| `/vps-list` | 已登记的机器和状态 |
| `/vps-use <别名>` | 设置当前机器 |
| `/vps-recipes [关键词]` | 列出菜谱 |
| `/vps-install <菜谱id> [--yes]` | 先出计划，加 `--yes` 才执行 |
| `/vps-tasks [任务号]` | 远端任务与日志 |
| `/vps-doctor` | 自查：插件状态、当前机器、连通测试、最近执行 |

都默认操作当前机器，也都可以加 `-h <别名>` 指定。

## 跟 AI 说话

注册了五个工具：`vps_hosts`、`vps_exec`、`vps_write_file`、`vps_task`、`vps_recipe`。

每段脚本执行前都会被判定级别，**AI 声明的级别只能把结果往高了抬，抬不低**：

| 级别 | 例子 |
|---|---|
| **只读** | `df -h`、`systemctl status`、`docker ps`、`journalctl` |
| **改动** | `apt-get install`、`sed -i`、`systemctl restart`、写文件 |
| **高危** | `rm -rf`、`mkfs`、改防火墙、`passwd`、`reboot`、`curl … \| sh` |

接下来问不问你，取决于这台机器的确认档位（机器 > 分组 > 全局）：

| 档位 | 只读 | 改动 | 高危 |
|---|---|---|---|
| **谨慎**（默认） | 自动 | 问 | 问 |
| **放手** | 自动 | 自动 | 问 |
| **全自动** | 自动 | 自动 | 自动 |
| 无头 / 没有审批界面 | 自动 | **拒绝** | **拒绝** |

配套三条保护：

- **改文件自动备份。** `vps_write_file` 先备份、原子写入、跑你给的校验命令，校验不过自动还原。备份绝不放在原目录——`sites-enabled/*` 这类通配会把备份文件也加载进去
- **连通性保险。** 改防火墙、SSH、网络配置时，先在服务器上埋一个定时恢复，再执行改动，然后用**全新连接**测试（必须绕开连接复用，否则测的是改动前就建好的连接，结果是假的）。连不上就等恢复触发
- **取消 = 转后台，不是杀掉。** 长操作跑在远端任务里，断线继续跑；把包管理器中途杀掉通常比让它跑完更糟。终止永远是显式操作

## 菜谱

目前内置 29 条：16 条只读查询，13 条安装 / 配置（Docker、Nginx、BBR、系统更新、系统清理、常用命令行工具、虚拟内存、时区、自动安全更新、fail2ban、Portainer、Uptime Kuma、Nginx Proxy Manager）。每条安装类菜谱都有 `detect`（装没装）、`plan`（给人看的步骤）、`run`（可重复执行）和 `verify`（**证明能用**——`docker info` 而不是 `docker --version`）。

自己加菜谱有两条路：

- **让 AI 存。** 它帮你做成一件可复用的事之后，说一句"存成菜谱"：它会把具体值抽成参数、补上 `detect`/`verify`，插件还会扫一遍有没有夹带凭据，然后落到 `$DSH_HOME/vps-manager/recipes/`
- **自己丢 YAML 文件**到那个目录

用户菜谱按不可信输入对待：级别取"声明的"和"静态判定的"里更严的那个，内容新增或改动后首次运行要确认一次。

## 面板

左边栏 → **VPS 管理**：

- **机器** —— 状态、地址、权限、分组；测连通；进入单台机器的设置页
- **应用商店** —— 装软件的（Docker、Nginx、Portainer、Uptime Kuma、fail2ban…）：选机器、看是不是已经装了、读脚本原文、再安装。长安装会转后台，页面轮询进度
- **系统维护** —— 不装东西、只改状态的操作（系统更新、清理、时区、虚拟内存、BBR、自动安全更新）。它们不是应用，所以不放在商店里
- **任务** —— 进行中和历史任务、实时日志、终止
- **机器设置页** —— 别名、地址、端口、用户名、跳板机、放公钥、主机指纹、确认档位、移除。改了连接字段，保存前会先试连
- **基础配置表单**（在机器设置页里）—— 填目标状态（时区、虚拟内存大小、BBR、自动安全更新、fail2ban、常用命令行工具），保存时**只执行和当前不一样的那几项**，每项一个远端任务，带实时进度

**对话头部有一个 VPS 开关**。打开，这个对话就绑定一台机器：命令不用写 `-h`，AI 也可以省略 `host`——你直接说话就行。关掉，这个对话就和服务器无关了。绑定是每个对话各自的，另一个窗口切机器影响不到这里。

输入框下方**平时什么都没有**，只有值得打断你的事才冒一行：后台任务还在跑、机器连不上、磁盘快满。其余的一切——查询、安装、提问——都是对话本身的事。

DSH 的「设置 → VPS 管理」只放全局设置（默认确认档位、保险时长、局域网开关、数据位置），机器列表只在面板里，两边不再重复

面板路由有三道锁：每次启动随机生成并注入页面的 token、同源校验、只收 JSON。**路由永远不提供自由命令执行和任意改文件。** 如果 DSH 的 Web 服务绑定在 `0.0.0.0`，所有会改东西的操作默认关闭，要自己去设置里打开。

## 它防不住什么

说清楚比含糊好——被误解的安全机制比没有更危险：

- 分级确认防的是 **AI 手滑**，不是防一个存心绕过它的 AI。静态判定识别不了所有变形写法，模型也可以用自带的 bash 工具直接够到你的服务器
- 宿主的沙箱管不到这个插件：它自己的 `spawn` 不在受限的 bash / 文件系统 / 终端能力之内
- 没有通用回滚。你有的是文件备份、连通性保险和可重复执行的菜谱。大改之前请到服务商后台打快照

## 数据放在哪

| 路径 | 内容 |
|---|---|
| `$DSH_HOME/vps-manager/hosts.yml` | 机器清单、分组、确认档位（可以手工编辑） |
| `$DSH_HOME/vps-manager/recipes/` | 你自己的菜谱 |
| `$DSH_HOME/vps-manager/audit/` | 每次执行一行 JSON（谁、哪台、干了什么、结果） |
| `~/.ssh/config.d/dsh-vps.conf` | 插件自己维护的连接配置 |
| `~/.cache/dsh-vps/`（远端） | 任务目录、日志、备份 |

插件不读取私钥内容，密码也从不经过它。
